WHAT D016-D ASKED FOR

  Two heterogeneous agentic reviewers, each executing in a fresh isolated
  session that can reach nothing but its frozen evidence bundle. Section 4
  forbids each reviewer independent access to the git repository, the project
  filesystem, home-directory files, arbitrary shell, web search, MCP servers,
  connectors and browser tools. Section 5 requires the Codex reviewer to run
  read-only from an empty temporary workspace with no repository mounted and no
  connector or web access. Section 6 requires all tools denied for the Google
  reviewer.

    Tool denial: ACHIEVED, and it is the reason the slot fails.

      Headless mode auto-denies every tool that would need a permission prompt.
      That is exactly the deny-all posture section 6 requires, enforced by the
      client rather than by instruction. But the agent invokes a command tool
      even for a prompt requiring no tool at all, and when that is denied the
      run produces no output whatsoever:

        jetski: no output produced — a tool required the "command" permission
        that headless mode cannot prompt for, so it was auto-denied.

      Observed identically on gemini-3.1-pro-high, gemini-3.7-flash-high and
      gemini-3.5-flash-medium; inside the jail and outside it; with and without
      --mode plan. A trivial prompt ("Reply with exactly: PREFLIGHT_OK") never
      returned text.

    So the Alternate reviewer can be given no tools, or it can produce a ruling,
    but not both. Which tool it wants was not determined: identifying it would
    have required granting command permission, and this session's own safety
    controls refused that. It was not pursued, because it could not change the
    outcome — the Primary slot fails independently.

    Also noted, and relevant to any future attempt: Antigravity discovers
    workspace customizations from a .agents/ directory by walking up from the
    working directory to the repository root. This repository HAS .agents/skills/.
    A reviewer run with its working directory inside the checkout would load
    this project's own agent instructions as context. The jail prevents this;
    running the CLI in the repository would not.

4. WHAT WOULD UNBLOCK IT

  Not a retry of the same approach. The jail already works; the boundary failed
  above it. An acceptable Primary reviewer needs an access path whose tool set
  the caller defines — a raw model API with an explicitly supplied tool list,
  or an account/workspace whose connector surface is administratively empty —
  rather than an assistant product whose account carries connectors. The same
  question must be asked of any Alternate before it is adopted.

  When such a path exists, the environment must carry, for each slot:

    A001_{SLOT}_REVIEWER_TOOL_DENIAL=VERIFIED_NO_REPOSITORY_NO_WEB

  That value is a positive claim that both halves were checked. The harness
  accepts no other value, and treats an unattested slot as not isolated.
