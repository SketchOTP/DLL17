# Decision log

Implementation decisions that are not architect directives. Architect decisions
live in the canonical Notion pages and in `.agent/RECORD.md`.

| ID | Date | Decision | Rationale |
|---|---|---|---|
| IMPL-0001 | 2026-08-12 | `core-math`, `core-crypto` and `core-state` apply only the Kotlin JVM plugin, and each carries a test asserting the Android framework is absent from its classpath. | Makes the E2E module boundary an enforced build fact rather than a convention. |
| IMPL-0002 | 2026-08-12 | `android-host` applies `com.android.application` and the Compose compiler plugin, and does not apply `org.jetbrains.kotlin.android`. | AGP 9 provides built-in Kotlin support and fails the build if the standalone plugin is applied. Frozen Kotlin 2.4.10 still governs the module. |
| IMPL-0003 | 2026-08-12 | The R000 registries are stored as versioned Markdown under `docs/architecture/registries/`. | Implementation Plan E2E mandates the registries but does not fix their location; Markdown keeps them reviewable and diffable before any code depends on them. |
| IMPL-0004 | 2026-08-12 | The root `LICENSE` was replaced with a proprietary, all-rights-reserved notice, superseding the inherited MIT grant. | Architect directive D005 resolved the recorded conflict in favour of the frozen `ProjectIdentityBuildContractV1` licensing clause. Repository visibility was explicitly left unchanged by the same directive. |
| IMPL-0005 | 2026-08-12 | The R000 qualification target is `system-images;android-37.0;google_apis;x86_64` under an x86_64 KVM-accelerated emulator. | It is the only available system image matching the frozen `compileSdk`/`targetSdk` 37 exactly, and the canonical determinism matrix already names the x86 Android emulator as a required target. |
| IMPL-0006 | 2026-08-12 | Resource evidence is recorded as `R000_MEASURED_BASELINE` observations only; no future production budget was assigned a number. | Directive D005 prohibits fabricating future targets. Measured observations of the empty shell are evidence; guessed ceilings would be invented constants that later qualification would have to unwind. |
| IMPL-0007 | 2026-08-13 | Canonical length prefixes are fixed 4-byte big-endian; variable-length integer encodings are prohibited. | Varint schemes admit non-minimal encodings, so the same value has more than one representation. Byte identity must be a property of the format, not of implementer discipline. |
| IMPL-0008 | 2026-08-13 | SHA-256 is implemented inside `core-crypto` rather than obtained from `java.security.MessageDigest`. | The algorithm's output is standardized but provider *resolution* is not: it differs between a desktop JDK and Android, moves as Conscrypt evolves, and can be reordered at runtime. Verified against FIPS 180-4 vectors and differentially against the platform provider on every target. |
| IMPL-0009 | 2026-08-13 | The PRNG is counter-based SplitMix64 (`PRNG_SPLITMIX64_V1`) with a 16-byte serialized state. | Smallest durable footprint of the candidates, integer-only with no table, public-domain reference implementation, and counter-based so a recovered substream cannot drift. |
| IMPL-0010 | 2026-08-13 | Fixed-point rounding is half away from zero on every rescaling operation. | Truncation toward zero and floor are both asymmetric about zero and inject a systematic drift into repeated decay over an organism lifetime. Banker's rounding removes bias but adds a tie-parity test that is easy to implement inconsistently. |
| IMPL-0011 | 2026-08-13 | 128-bit intermediates use explicit 32-bit limbs; `Math.multiplyHigh` is prohibited and `BigInteger` is test-only. | `Math.multiplyHigh` reached Android only at API 31 while the frozen `minSdk` is 29, so it would compile against `compileSdk` 37 and throw `NoSuchMethodError` on a supported device — a failure no desktop test would catch. |
| IMPL-0012 | 2026-08-13 | Canonical identifiers are restricted to an ASCII subset and canonical state carries no natural-language text. | Removes Unicode normalization, locale-sensitive case folding and ICU collation from the canonical path entirely. Android's Unicode version advances independently of the JDK's, so this is eliminated by policy rather than tested around. |
| IMPL-0013 | 2026-08-13 | R001 determinism is qualified through an Android instrumented test rather than through the shell UI, leaving the R000 shell untouched. | Determinism is a property of ART executing the canonical core, not of Compose. Changing the shell would also have invalidated the R000 launch harness and its closed-gate evidence. |
| IMPL-0014 | 2026-08-13 | The qualification bundle tool now pins a closed phase to its qualified commit and verifies that phase from `git show`, instead of from the working tree. | A defect found during D006: R000's bundle verified against the working tree, so any later phase editing a shared build file or registry would have broken a gate that had already passed. Evidence of a past qualification must not depend on the present. |
| IMPL-0015 | 2026-08-13 | The durable medium for R001 is an in-process append-only byte log, not a database. | R001 owns the durability *contract* — append-only ordering, acknowledgement, `reduce == replay`. Persistence *semantics* are R002's `ContinuityDurabilityContractV1`, and implementing them here would pre-empt a later phase's decisions. |
| IMPL-0016 | 2026-08-13 | Continuity lives in a new pure-Kotlin `core-continuity` module rather than inside `core-state`. | R002 adds a large, cohesive subsystem — clocks, trust, reconciliation, durability, platform protection, encryption — and folding it into the R001 determinism kernel would have made the closed R001 surface harder to reason about. The module boundary also keeps the Android framework out of continuity logic by construction. |
| IMPL-0017 | 2026-08-13 | Canonical durations are `i64` milliseconds, never `Fixed64`. | Nanoseconds overflow `i64` inside the range a one-year absence plus a lineage age can reach. `Fixed64` seconds would put durations into saturating arithmetic where a clamp is silently plausible, and a duration that saturates should be a loud failure. |
| IMPL-0018 | 2026-08-13 | `AEAD_CHACHA20_POLY1305_V1` is implemented in project, from RFC 8439, rather than taken from `javax.crypto`. | Identical reasoning to owning SHA-256: the algorithm is standardized but which provider implementation runs is not, and a record a device can write but a later build cannot read is unrecoverable data loss. ChaCha20-Poly1305 is add-rotate-xor only, has no generated tables, and needs no AES hardware path. |
| IMPL-0019 | 2026-08-13 | AEAD nonces are derived from `(keyEpoch, durable sequence)` rather than drawn randomly. | A random nonce puts a CSPRNG in the durable write path — the exact provider dependency R001 eliminated — and makes an encrypted record irreproducible in a fixture. Derivation makes uniqueness structural rather than probabilistic. |
| IMPL-0020 | 2026-08-13 | Blind-credit replenishment carries its division remainder in durable state. | Truncating lets an attacker farm a systematic loss by fragmenting sessions; rounding to nearest lets them farm a gain the same way. A carried remainder makes the grant a pure function of total verified time, with no fragmentation strategy. |
| IMPL-0021 | 2026-08-13 | Uncertainty debt beyond the global cap is forgiven at accrual, not retained in a shadow ledger. | A retained balance is a liability the user cannot see and cannot discharge, which is the delayed punishment bomb the canonical architecture prohibits by name. Forgiving at accrual makes the outstanding balance always equal to what could actually be collected. |
| IMPL-0022 | 2026-08-13 | Blind-credit consumption does not advance `verifiedTimeTotalMillis`. | That counter gates replenishment, debt eligibility and rearm. If unverifiable time fed it, a reboot loop could manufacture the verified time needed to buy more blind time. |
| IMPL-0023 | 2026-08-13 | Reconciliation plans a deterministic event sequence and folds it through the ordinary reducer, rather than mutating state directly. | It makes `reduce == replay` hold for a reconciliation, and it makes an interrupted reconciliation resumable — a reconciliation that wrote state directly would leave nothing in the journal to replay. |
| IMPL-0024 | 2026-08-13 | Chunk boundaries are measured from the start of the absence, not from the end. | Measuring from the end makes the chunk sequence depend on the total, so two absences overlapping in real time would reconcile the same interval with different boundaries and different rounding. |
| IMPL-0025 | 2026-08-13 | An anomalous same-boot interval grants blind credit only, rather than treating monotonic uptime as authoritative regardless of wall-clock disagreement. | Deliberately stricter than the canonical text. It can only ever grant less progression, never more, and it costs nothing an attacker could want. |
| IMPL-0026 | 2026-08-13 | A structurally incomplete tail record is skipped; a structurally complete record that fails authentication is always a `STORAGE_FAULT`. | The two failures look similar and mean opposite things. Tolerating an unauthentic record would let one be silently dropped or silently accepted out of position; refusing a torn tail would make an interrupted write unrecoverable. |
| IMPL-0027 | 2026-08-13 | R002.12 recovery cryptography and the storage provider are left `BLOCKED_SPEC_RECOVERY_CRYPTOGRAPHY` and `BLOCKED_SPEC_RECOVERY_PROVIDER` rather than implemented. | Implementation Plan E2E R002.12 requires `RecoveryCryptographyContractV1` to be frozen before recovery cryptography is written, and D007 authorized freezing `ContinuityDurabilityContractV1` only. Inventing a KDF, a mnemonic encoding or an epoch protocol inside persistence code is exactly what that clause prohibits. |
| IMPL-0028 | 2026-08-13 | The A000 spike lives in `research/aliveness-spike/` as four Gradle modules that depend only on `:core-math`, and a test reads every spike source's import list. | The canonical plan permits exactly one production dependency, but a Gradle declaration cannot enforce it: `core-math` publishes `core-crypto` as `api` for lookup-table verification, so it is on the compile classpath regardless. The enforceable boundary is the import list, so that is what is checked. |
| IMPL-0029 | 2026-08-13 | Candidate utility is decomposed into six additive per-group contributions rather than computed as one scalar. | `CoalitionValueFunctionV1` requires the controller to be recomputed from the identical pre-action state with only a coalition enabled. Additive per-group contributions make that recomputation exact rather than approximate, and turn 64 coalition evaluations per scored action into 64 sums instead of 64 controller runs. |
| IMPL-0030 | 2026-08-13 | The coalition candidate set is fixed from the pre-action state; a coalition varies utility contributions only, never eligibility. | Disabling a group's contribution is not a claim that the organism never had that candidate. Letting coalitions change eligibility would make `v` ill-defined, because the coalitions would be scoring different games. |
| IMPL-0031 | 2026-08-13 | Preference, habit and relationship are error-corrected estimates that move toward the observed outcome, not accumulators. | The accumulator form was implemented first and is unusable: anything with a net-positive outcome pins at the bound, so a reliable food source and an unreliable one become indistinguishable and no contingency reversal can be observed. This is recorded as a mechanism-design finding, not a bug fix. |
| IMPL-0032 | 2026-08-13 | Danger avoidance in A000 is entirely learned; the habitat's `UNSAFE` label does not depress utility or promote withdrawal. | An organism that innately avoids the aversive object can never acquire a conditioned fear, which makes the avoidance and extinction arms untestable. Learned avoidance also puts the effect in the learned-valence coalition group where the attribution analysis can see it. |
| IMPL-0033 | 2026-08-13 | `Fx.mul` and `Fx.div` use a `Long`-range fast path that falls back to the frozen library, with an equivalence test. | The library computes every product through a 128-bit intermediate whose division is a bit-by-bit loop — correct for canonical arithmetic, and the dominant cost of a simulator evaluating tens of millions of products. `SpikeNumericsTest` compares the two across boundary values and a 20,000-sample sweep. |
| IMPL-0034 | 2026-08-13 | The A000 kernel and the envelope search use `java.security.MessageDigest` and `StrictMath`, not `core-crypto`. | Importing `core-crypto` would exceed the one production dependency the canonical plan permits. Research evidence digests and analysis statistics are not canonical organism computation, and `StrictMath` is specified bit-for-bit so the measurements stay reproducible. |
| IMPL-0035 | 2026-08-13 | The curiosity-envelope search reports `EMPTY_THRESHOLD_INCOMPATIBILITY_CANDIDATE` and stops, rather than adjusting a threshold. | `CuriosityEnvelopeFeasibilityV1` gives the independent gate reviewer, not the implementer, the choice between the threshold-revision path and the mechanism-revision path, and allows exactly one threshold-only revision ever. Spending it unilaterally would be the most expensive possible shortcut. |
| IMPL-0036 | 2026-08-13 | R002's qualification bundle is pinned to its qualified commit `7f6f37fa`. | A000 adds Gradle modules and therefore edits `settings.gradle.kts`, an R002 constituent. Same defect IMPL-0014 fixed for R000: a closed gate must not break because a later track exists. |
| IMPL-0037 | 2026-08-13 | Rest and sleep are Tier 3 only when rest is actually low; the nocturnal preference lives in the utility term. | Promoting rest for the whole night regardless of need meant Tier 3 outranked Tier 4 every night. One action took nearly half the tick budget and the successor of almost anything was that action, which is most of what the D008 anti-convergence failure was measuring. |
| IMPL-0038 | 2026-08-13 | Skill proficiency added to the A000 candidate: bounded competence per action-and-object, grown by validated practice and faded by disuse. | Canonical §9 item 8, and the only route to long-run individuality that survives a homeostatic drive model. Every organism must eat and sleep about as much as every other, so individuality has to live in what they become good at. |
| IMPL-0039 | 2026-08-13 | Re-exploration is driven by per-option outcome uncertainty, not by random action noise. | Uncertainty falls when an option is sampled and behaves as expected, rises while it is neglected, and jumps on prediction error; appetite for acting on it rises with frustration and is damped by stress and fear. Every re-sample therefore has a citable cause in the trace, which arbitrary exploration would not. |
| IMPL-0040 | 2026-08-13 | Episodic history removed from FULL rather than retained in revised form. | A context-conditioned, salience-retained revision, measured over five seeds with circadian structure added to the habitat so it had something to learn, still did not increase history-dependent individuality. The canonical rule is that a mechanism which does not earn its complexity does not enter production, and the same discipline applies inside the research candidate. |
| IMPL-0041 | 2026-08-13 | Anti-convergence is enforced by three bounded mechanisms rather than by the curiosity oscillator alone: action satiation, a per-object engagement refractory, and a metabolic cost for vigorous activity. | Recent-inspection inhibition cannot do it alone. Under continuous engagement every object saturates, and a uniformly saturated term stops discriminating between them. The three bounds act on different things — the kind of activity, the object, and the body — so none of them has to be large. |
| IMPL-0042 | 2026-08-13 | Preference updates only on outcomes that carry non-zero valence. | Once the revised candidate looked at things far more often than it consumed them, averaging over mostly-neutral glances scored a reliably good food source at zero. A neutral non-event is not evidence about value. |
| IMPL-0043 | 2026-08-13 | Only voluntary activities are recorded as resumable, and withdrawal is a bounded reaction to a live threat on every route into it. | Recording a retreat as resumable created a punishment loop: withdraw from the aversive object, be interrupted, "resume" by engaging it again, be punished — eighty-seven times a virtual day. Treating damaged safety as blanket grounds for Tier 0 withdrawal gave every object present a top-priority candidate. |
| IMPL-0044 | 2026-08-13 | The curiosity-envelope thresholds were not touched during remediation, and the programme's single threshold-only revision remains unspent. | The architect took the mechanism path over the threshold path. The same grid, seed matrix and requirements that returned zero feasible points under D008 return twenty-seven robust ones under D009, which settles the question the empty result posed. |
| IMPL-0045 | 2026-08-13 | The A001 statistical primitives — incomplete beta and gamma, Student t, exact noncentral-t power, exact binomial — are implemented in the research module rather than taken from a library. | The research track is permitted exactly one production dependency and no statistical library is on that list. A preregistered decision rule that turns on a p-value should also be readable end to end by the reviewer who has to adjudicate it. Every routine is checked against published reference values, including the standard one-sample t sample sizes for Cohen's d of 0.2, 0.5 and 0.8. |
| IMPL-0046 | 2026-08-13 | Power uses the exact noncentral-t distribution, evaluated by numerical integration, rather than a normal approximation with a t correction. | At the sample sizes A001 will actually run, the approximation and the truth differ by whole participants, and the difference falls on the side of underpowering. An underpowered scored attempt consumes one of three and produces an uninterpretable null. |
| IMPL-0047 | 2026-08-13 | The variance-pilot information barrier is enforced by type visibility, not by procedure: the released type declares two fields and the sealed analysis type is private and never returned. | Written access rules are advisory and this repository enforces exactly one of them in code. The seal is the one that matters, because a FULL team that learns the pilot leaned favourable will make different decisions in good faith. It is proven two ways — by reflecting over the released type's declared members, and by showing that two pilots with opposite outcomes produce byte-identical output. |
| IMPL-0048 | 2026-08-13 | Ablation arms are powered at the most conservative Holm step, alpha divided by the number of arms, rather than at the uncorrected alpha. | Powering at the uncorrected alpha reliably produces a family that is significant before correction and not after, which is the exact failure multiplicity correction exists to prevent. It costs participants and it is the honest cost of testing three mechanisms. |
| IMPL-0049 | 2026-08-13 | The activation state and the human-recruitment gate are derived from the audit items rather than declared alongside them. | A declared gate state drifts out of agreement with its own checklist, always in the permissive direction. Deriving it means a prerequisite that goes missing appears as a blocker automatically, and the test proves the derivation in both directions. |
| IMPL-0050 | 2026-08-13 | A000's qualification bundle is pinned to its qualified commit `4a2b1e4c`, and D010's work is bundled separately as `A001PRE`. | Third application of the defect IMPL-0014 fixed for R000: D010 legitimately edits A000 artifacts — the kernel gains the preregistered third ablation cohort, the gate record gains a figure reconciliation — and a gate that has already passed must not depend on what a later directive does. |
| IMPL-0051 | 2026-08-13 | The scripted comparator's full contents are disclosed by a generator that reads the implementation, rather than described in prose. | The independent owner has to judge whether the baseline is a fair comparator, and a description can drift away from the thing it describes. It also replaced an ad-hoc diagnostic whose numbers were quoted in the D009 report and checked by nothing. |
| IMPL-0052 | 2026-08-13 | The graded instrument is one item rather than a battery, and its anchors name no mechanism. | The endpoint is a difference between two administrations of the same question, and every extra item is another place for the two administrations to diverge for reasons unrelated to the creature. Naming a mechanism in an anchor would tell the rater what to look for and make the ablation arms unusable. |
| IMPL-0053 | 2026-08-14 | The production persistence backend is a single-writer append-only log with one `fsync` per acknowledged commit, not Room and not SQLite. | Selected from measurement on ext4/NVMe: SQLite in WAL mode cost 5.3x the p99 commit latency and 4.4x the storage for a workload that never issues a query, never updates in place, and reads only by replaying the whole history. A general-purpose engine also puts its own crash recovery underneath ours, so a durability claim would rest on two engines agreeing rather than on one fsync returning. |
| IMPL-0054 | 2026-08-14 | The commit force is `force(true)`, metadata included, rather than `force(false)`. | A growing file's length is metadata, so a data-only force can acknowledge a record whose length update was lost. The measurement showed the safer option costs 1%, which is inside the run-to-run spread. |
| IMPL-0055 | 2026-08-14 | A wrong frame magic or an impossible frame length is corruption wherever it appears; only running out of bytes is a torn tail. | A partial write cannot produce either, because the magic is the first thing written and a length is wholly present or wholly absent. The first implementation treated a broken *first* frame as an empty journal, which would present a corrupt installation as a device with no organism on it — the worst failure available here. |
| IMPL-0056 | 2026-08-14 | Capacity exhaustion refuses the write without setting a sticky fault, so a full journal stays readable and compactable. | Compaction has to read the survivors before it can delete anything. A full journal that could not be read or compacted would have no exit except losing history, which is the failure the emergency reserve exists to prevent. |
| IMPL-0057 | 2026-08-14 | The data-encryption key is random and wrapped, never derived from the device secret. | Rotation then rewraps one key instead of re-encrypting every record ever written, and an interrupted rotation can be abandoned safely because the data key never changed. |
| IMPL-0058 | 2026-08-14 | The recovery root is 256 bits with HKDF, not a passphrase with a memory-hard KDF. | Entropy does the work the KDF would otherwise have to. Iterating a hash over a full-entropy secret buys nothing an attacker cannot ignore, and it costs a slow battery-hungry step in the one flow where the user is already frightened. |
| IMPL-0059 | 2026-08-14 | The recovery secret is encoded as checksummed base32 groups rather than a mnemonic word list. | The contract fixes the bits, not the rendering, so a word list can be added later as presentation without touching anything cryptographic. A list needs 2,048 curated words per language; base32 is unambiguous and language-neutral. |
| IMPL-0060 | 2026-08-14 | The cold-package manifest is plaintext, MAC'd, and bound into the ciphertext's associated data. | A provider and a destination must be able to check identity, epoch, sequence and size before anyone has a key, so a stale or foreign package is refused without a decryption attempt. Binding it into the AAD is what stops a provider serving one package's body under another's manifest. |
| IMPL-0061 | 2026-08-14 | Cold recovery verifies the package before contacting the authority, and advances the epoch before writing local state. | The order is the security property: verifying first means a corrupt package never consumes an epoch, and advancing first means a crash mid-restore cannot leave two devices believing they hold the current epoch. |
| IMPL-0062 | 2026-08-14 | A challenge nonce is spent even when the proof fails. | A nonce that survives a failed proof is a nonce an attacker can grind against. |
| IMPL-0063 | 2026-08-14 | `core-persistence` does not depend on the identity-authority service; the qualification kernel takes an authority as a parameter. | The architectural claim is that the authority is separately deployable and that ordinary local operation never reaches it. A compile-time dependency from a core module would quietly falsify both, so `ModuleBoundaryTest` asserts the service class is absent from the core classpath. |
| IMPL-0064 | 2026-08-14 | Persistence benchmarks and the R012 kernel refuse to run on tmpfs. | The first benchmark run landed in the system temp directory, which is tmpfs on this machine, where fsync is a no-op. It reported 2 microsecond commits and would have selected a backend on numbers that measured nothing. |
| IMPL-0065 | 2026-08-14 | Process-death fixtures use a child JVM killed with `Runtime.halt`, and the power-loss claim is disclosed as unproven rather than implied. | `halt` skips shutdown hooks and finalizers, so it is a real abrupt death. It does not empty the OS page cache, so no test here distinguishes forced bytes from unforced ones; that claim rests on the force-per-commit policy and is stated as such. |
| IMPL-0066 | 2026-08-14 | The Android key container is an AndroidKeyStore **HMAC-SHA256** key whose root secret is `HMAC(key, label)`, not an AES key. | `LocalStorageCryptographyContractV1` needs the root secret to be both non-exportable and *stable across restarts*. An AES key satisfies the first and not the second: `Cipher` in GCM generates its own IV, so encrypting a fixed label yields different bytes every time, and pinning the IV would be nonce reuse on a long-lived key. The raw HMAC key never leaves the keystore; what leaves is a derived secret, and a second label yields the device fingerprint without a second key. |
| IMPL-0067 | 2026-08-14 | Opening the Android key container never generates missing material; creation is a separate call, and a birth requires *two* absent witnesses — no key state on disk **and** no container material. | A device whose keystore was lost looks exactly like a device that never had an organism. If opening generated the missing key, the container would work perfectly, open nothing, and the natural next step for any caller reading "no readable state" as "no organism" is a birth. Refusing to generate is what turns that path into `CONTAINER_UNAVAILABLE`. |
| IMPL-0068 | 2026-08-14 | Backup and device-transfer exclusion is verified from the **built** package via `aapt2`, following the merged manifest's own resource references, in addition to the source and installed-package checks. | Correct rule files that the merged manifest fails to reference are silently permissive, because Auto Backup is opt-out by default. The release variant also renames compiled resources, so following the manifest's reference is the only way to read the rules the platform would actually load. |
| IMPL-0069 | 2026-08-14 | The Android crash process is a debug-variant component, and its absence from the release package is asserted against the built artifact. | A component whose entire purpose is to die abruptly while holding canonical storage open has no business shipping. "It is in a debug source set" is a claim about the build files; the package is the artifact. |
| IMPL-0070 | 2026-08-14 | `R012PerformanceHarness` names its filesystem through a fallback chain rather than through `Files.getFileStore` alone. | Android refuses `getFileStore` with a `SecurityException`, so the harness could not run on a device at all. The fallback reads the process's own mount table and the last resort is "unknown" rather than a guess, because a wrong filesystem name is how a two-microsecond fsync gets recorded as a durable commit. |
| IMPL-0071 | 2026-08-14 | `R012-QB-1` is pinned to its qualified commit `afd0ecdb`, and D012's work is bundled separately as `R012DEV-QB-1`. | Fifth application of the defect IMPL-0014 fixed for R000. D012 legitimately edits an R012 constituent — the performance harness, to make it run on Android at all — and a gate that has already passed must not break because a later directive exists. |
| IMPL-0072 | 2026-08-14 | The wrapping epoch and the data key's identity are separated, and a record is decrypted under **its own immutable stored context** rather than under the container's current wrapping epoch. `LocalStorageCryptographyContractV2`. | V1 used one number for both, so the first rotation of the device wrapping material made the entire journal unreadable — key hygiene that deletes the organism. The record byte layout is unchanged; only the source of that one value moved. Informed by the DEK/KEK separation in established envelope encryption, recorded as `PA-0001` with disposition REFERENCE. |
| IMPL-0073 | 2026-08-14 | The pre-check that refused a record whose epoch differed from the container's was removed rather than relaxed, and the guarantee left to the AEAD tag. | The context is inside the AAD, so a rewritten context, a foreign data key, and a relocated record all still fail authentication — `FX-EPOCH-CONTEXT-AUTHENTICATED-01` forges four header fields and all four are refused. What the pre-check actually did was refuse *honest* records for carrying a value that had legitimately changed. Cryptography is the stronger of the two guards and the only one that was load-bearing. |
| IMPL-0074 | 2026-08-14 | Key state migrates from schema `231` v1 to v2; **no journal record is rewritten**. | The migration adds `dataKeyId = 1` to one small file. Every V1 organism has exactly one data key and has never rotated it, because V1 had no way to, so the migrated identity is the initial one for every installation in existence. Rewriting history on a schema bump would make migration cost proportional to the length of the organism's life, and would put every record at risk to change a field none of them carry. |
| IMPL-0075 | 2026-08-14 | `dataKeyId` is introduced now but data-key rotation is **not** implemented. | The field costs four bytes and removes the need for a second layout change later. Implementing the rotation itself needs a separately frozen design for key rings, historical-key retention, re-encryption, compaction interaction and recovery compatibility, and D013 authorized none of it. A wrapping rotation must never be quietly turned into a DEK rotation: one rewraps 32 bytes, the other rewrites a life. |
| IMPL-0076 | 2026-08-14 | The corrected substrate is `R012-QB-2` and the D013 device run is `R012DEV-QB-2`; `R012-QB-1` stays pinned at `afd0ecdb` and `R012DEV-QB-1` is newly pinned at `4700b076`. | Sixth application of IMPL-0014, and the first where a *blocked* bundle is pinned. D013 makes `DV-KS-ROTATION-READBACK-01` pass; if R012DEV-QB-1 followed the working tree, the negative evidence D012 filed would silently become a passing report. A resolved finding that leaves no trace is indistinguishable from a finding nobody made. |
| IMPL-0077 | 2026-08-14 | The network recovery provider is a project-owned S3-compatible adapter with project-owned SigV4 signing, not the AWS SDK for Java v2 and not the MinIO client. | The provider has to run on the destination device during a cold recovery, and AWS states it has no plans to expand Android support for the v2 Java SDK, while the MinIO client resolves BouncyCastle, Guava, Jackson and OkHttp — a second cryptographic provider on a device whose key hierarchy is already frozen and qualified. The scope actually needed is four operations plus a signature built from primitives this project already owns. Recorded as `PA-0002` with disposition BUILD. `AndroidApiSurfaceTest` reads the compiled classes back so the justification cannot quietly stop being true, and MinIO — an independent implementation of AWS SigV4 — authenticated every request, which is the difference between a compatible signer and a self-consistent one. |
| IMPL-0078 | 2026-08-14 | The identity-authority transport is `com.sun.net.httpserver` with canonical-envelope bodies, not Ktor, Javalin, http4k or Spring Boot, and not JSON. | Unlike IMPL-0077 no candidate was unsuitable, and the honest statement is that a capable option was declined. The service has four endpoints, one bounded binary body under 128 bytes, no routing beyond a path match and no session state; a framework would contribute a dependency tree to keep current inside the process that decides which device owns an organism. Canonical bytes reuse a codec that is already frozen, so the wire format needs no parser to harden and the body ceiling is a real defence. Costs are recorded rather than hidden: no HTTP/2, no in-process TLS, and a reverse proxy is required. Recorded as `PA-0003`. |
